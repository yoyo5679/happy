# 해피케어복지용구 — 고객 참여형 돌봄 자가진단 툴

블로그·유튜브 방문자가 클릭 몇 번으로 답하면 맞춤 결과를 보여주고, 결과 화면에서 스토어 상품 페이지로 자연스럽게 연결하는 리드 생성용 웹 툴입니다.

| 경로 | 기능 |
|---|---|
| `/` | 첫 화면: 보호자용/기관 선생님용 탭 + 세 도구 (순서는 `src/config/tools.ts`) |
| `/person` | ② 어르신 상태로 찾기 (9문항: 걱정·걷기·일어서기·누워 있는 시간·피부·소변·기억·외출 → Top 5) |
| `/rooms` | ① 장소별로 찾기 (직접 그린 평면도에서 욕실·침실·거실·현관 선택, `?room=bath` 바로가기) + 1분 안전 점검 연결 |
| `/check` | ② 안의 가정 낙상 위험 점검표 (13개 항목 → 위험도 + 필요 용품) |
| `/grade` | ③ 등급·혜택 확인 (공식 인정조사표 5개 영역을 따른 18문항 장기요양등급 모의 계산, 결과에 '어떻게 계산했나요?' 설명 → 예상 등급 + 추천 용품) |
| `/recommend` | 예전 질문형 '집 맞춤' 주소 → `/rooms`로 자동 연결 |
| `/partner` | 방문요양기관 선생님용 도우미 (도구 모음, 품목별 내구연한·급여한도, 본인부담률 표) |
| `/budget` | 예산으로 세트 짜기 (160만원 중 쓸 금액 + 필요한 묶음 → 선택한 예산 기준 실속형(가장 합리적인 모델)·표준형(실속형과 예산의 중간)·든든형(예산에 가장 가깝게, 수량은 `QTY_CAP` 급여 수량 한도 안에서) 세트, 대여는 기본 3개월, `?c=품목,품목`·`?g=묶음`·`?b=금액`으로 미리 채우기) |
| `/catalog` | 해피케어몰 진열 상품 전체(344개 모델) + 본인부담률(15/9/6/0%)별 본인부담금 |

## 상품 데이터

**쇼핑몰(happycaremall.com)에 진열된 상품이 기준**입니다. 모든 상품 카드는 쇼핑몰의 해당 상품 페이지로 바로 연결됩니다.

- **`src/data/products.json`** — 쇼핑몰 상품 엑셀에서 생성. 모델별 대여(월)/구입 가격, 상품 URL, 품절 여부, 이미지
  - 카탈로그와 모델명이 일치하는 상품(259개)은 급여코드와 카탈로그 사진(`public/products/`)을 붙였고, 나머지는 쇼핑몰 대표 이미지를 씁니다.
  - 품절 상품은 추천 결과에 나오지 않고, 전체 모델 페이지에서는 맨 뒤에 "품절"로 표시됩니다.
  - 본인부담금은 쇼핑몰과 같이 10원 미만 절사합니다.
- **`src/data/products.ts`** — 품목 이름/설명, 결과 화면에 먼저 보여줄 상품(`featured`) 지정

## 상품 갱신 (쇼핑몰 상품을 추가·수정했을 때)

아임웹 관리자에서 상품 엑셀을 다시 내려받아 실행하세요 (Python `openpyxl` 필요).

```bash
python3 scripts/catalog/build_from_mall.py 상품목록.xlsx scripts/catalog/catalog.json src/data/products.json
```

`scripts/catalog/catalog.json`은 이로움케어 카탈로그 PDF에서 추출한 급여코드·가격 데이터이고(`parse_prices.py`, `extract_images.py`로 생성), 쇼핑몰 상품과 모델명으로 매칭하는 데 씁니다.

## 쇼핑몰 장바구니 담기 (/budget)

예산 세트(실속·표준·든든) 카드마다 "🛒 세트 장바구니에 담기" 버튼이 있어요. 누르면 해피케어몰 장바구니로 가서 세트 상품이 한 번에 담깁니다.

- 주소: `https://happycaremall.com/shop_cart?hc_cart=1330r,1004x4&hc_r=15&hc_m=3` (`src/lib/cart.ts`에서 만듦)
  - `hc_cart`: 쇼핑몰 상품번호(idx) + `r`(대여) + `x수량` · `hc_r`: 본인부담률(%) · `hc_m`: 대여 개월
- 담는 일은 쇼핑몰 쪽 스크립트 **`imweb/cart-import.html`** 이 합니다. 아임웹 관리자 → 설정 → SEO → 고급 설정 → 공통 코드 삽입 → **Footer Code** 맨 끝에 붙여 넣고 저장하세요.
  - 상품마다 필수옵션을 읽어 본인부담률(`15%`·`9%`·`6%`·`0%` 글자로 찾음) → 대여기간(고른 개월 이하에서 가장 긴 기간 + 모자란 달은 `1개월 연장`) → 색상 등 나머지는 첫 번째 값으로 고릅니다.
  - 기간 옵션 없이 월 단위로 등록된 대여 상품(정상가 10만원 미만)은 개월 수만큼 담습니다.
  - 이미 장바구니에 있는 상품은 건너뛰고, 품절·판매중지 상품은 담지 않고 결과 창에 알려 줍니다.
  - 쇼핑몰 옵션 이름 규칙(`본인부담금 15%(…)`, `일반 15%(월 …원)`, `3개월`·`6개월`·`1개월 연장`)을 바꾸면 이 스크립트도 확인하세요.
  - Footer Code 편집기는 HTML 기호를 풀어서 저장하므로 이 스크립트에는 HTML 기호를 쓰지 않습니다.
- 아임웹은 배송방법(택배·직접배송)이 다른 상품을 한 주문으로 결제하지 못합니다("배송방법이 일치하는 상품끼리 결제할 수 있습니다"). 그래서 "전동침대 방문설치" 배송 템플릿도 **택배**(무료)로 두고, **`imweb/install-label.html`**(Footer Code)이 상품 상세·장바구니의 전동침대 배송 방법을 '방문설치'로 바꿔 보여 줍니다. 장바구니에서는 상품명 앞 `|전동침대|`로 침대 줄을 알아봅니다.
- 장바구니에 담기는 가격은 쇼핑몰 기준이라, 쇼핑몰 상품을 바꾼 뒤에는 위 "상품 갱신"으로 `products.json`도 꼭 다시 만들어 주세요 (안 그러면 도구 화면 금액과 장바구니 금액이 달라져요).

## 쇼핑몰 카테고리 필터 칩 (Footer Code)

쇼핑몰 카테고리 페이지의 필터 칩을 품목마다 다르게 보여 줍니다 (예: 지팡이 = 네발·가벼운 300g 이하·100cm 이상 길게, 전동침대 = 최저·최고 높이·등판 각도·최대하중·폭). 복지용구는 본인부담금이 정해져 있어 가격대 칩은 쓰지 않습니다. `PAGES`에서 메뉴를 `"KEEP"`으로 두면 그 페이지는 쇼핑몰 원래 칩을 그대로 씁니다.

- 쇼핑몰 쪽 코드: **`imweb/category-filter.html`** (Footer Code 맨 끝에 붙여 넣기). 칩을 누르면 그 카테고리 상품 전체를 아임웹 목록 API로 한 번 받아 함께 거르고, 결과는 12개씩 보여 줍니다.
- 칩 데이터: **`public/imweb/filters.json`** → `https://happycare.pages.dev/imweb/filters.json` (`public/_headers`로 쇼핑몰에서 읽기 허용)
- 상품이 바뀌면 관리자 상품 → 엑셀 다운로드 → **상품 정보 일괄 수정용**(요약설명 규격표 포함)을 받아 다시 만들고 배포하세요.

```bash
python3 scripts/catalog/build_filters.py 상품정보수정용.xlsx public/imweb/filters.json
```

칩 이름·기준은 `scripts/catalog/build_filters.py`의 `RULES`, 메뉴 주소와 품목 연결은 `PAGES`에서 바꿉니다. 판별은 상품명 앞 `|분류|`와 요약설명의 '제품 주요규격' 표(중량·규격·재질·계절·흡수량 등)를 씁니다.

## 배포 (Cloudflare Pages, 무료)

사이트는 정적 HTML로 내보냅니다(`next.config.ts`의 `output: "export"` → `out/` 폴더). 서버가 필요 없어 어느 정적 호스팅에도 올릴 수 있습니다.

1. https://dash.cloudflare.com 가입 → **Workers & Pages → Create → Pages → Connect to Git**
2. GitHub 연결 후 저장소 `yoyo5679/happy` 선택
3. 빌드 설정
   - Production branch: 배포할 브랜치
   - Framework preset: **Next.js (Static HTML Export)**
   - Build command: `npx next build`
   - Build output directory: `out`
   - Node 버전은 `.node-version`(22)으로 지정됨
4. **Save and Deploy** → `프로젝트이름.pages.dev` 주소가 생깁니다.
5. 내 도메인: 프로젝트 → **Custom domains** → `care.happycaremall.com` 추가 → 안내되는 CNAME 값을 도메인 관리 화면에 등록
6. 주소가 바뀌면 `src/config/site.ts`의 `siteUrl`을 바꿔 주세요 (공유 미리보기용).

현재 주소: **https://happycare.pages.dev**

이후 GitHub에 push할 때마다 자동으로 다시 배포됩니다.

## 고객 장부 기능 종료

고객 장부·보호자 조회·동의서·아임웹 주문 가져오기 UI와 처리 코드를 제거했습니다. `/my`, `/staff`는 종료 안내만 표시하며, 기존 장부 API는 모든 메서드에서 410을 반환합니다. 브라우저의 이전 링크 키(`hc_my_k`)와 직원 인증값(`hc_staff`)은 새 페이지 접속 시 제거합니다.

운영 API는 연결된 D1에서 장부 전용 `items`, `consents`, `imweb_orders`, `recipients`, `kv` 테이블의 데이터를 삭제하고 남은 행이 없는지 확인합니다. 공개 기관 정보 `ltc`는 유지합니다. 연결되지 않은 DB, 다른 환경의 DB, 호스팅 백업·이전 배포·Git 기록은 이 마이그레이션의 삭제 대상이 아닙니다. 더 이상 사용하지 않는 Cloudflare IMWEB_API_KEY/IMWEB_SECRET_KEY는 설정에서 제거할 수 있습니다.

  `python3 -I scripts/ltc/build.py 시설별현황.xlsx 평가결과.csv` → `public/ltc/facilities-{시도}.json`, `meta.json`
- 기관 관리 화면은 종료했습니다. 기존 인증된 `/api/staff/ltc/*` 관리 API와 공개 `/api/ltc/*` 검색 API는 유지합니다.
- Cloudflare 암호: `KAKAO_REST_KEY`(주소→좌표, 동네 검색), `DATA_GO_KR_KEY`(전화번호: 공단 일반현황 API, 30일 저장)
- 정렬: 가까운 순(기본) · 평가등급 순(고른 종류 중 가장 좋은 등급, 같으면 거리) · 오래된 순(지정일)


## 복지용구 제원표 `/sizelist`

가가온 **2026년 2호 카탈로그(0915, 70쪽)**의 직접 확인한 수치를 기존 해피케어몰 등록 제품에 연결합니다. 기존 Cloudflare Pages 정적 배포를 유지합니다.

- `src/data/size-guide.ts`: 제품 목록의 유일한 기준은 `products.json`입니다. 급여코드 또는 같은 품목 내 정확히 정규화한 모델명으로 제원을 연결하며 카탈로그 단독 모델은 노출하지 않습니다.
- 구입·대여가 모두 품절인 상품은 제원표·검색·비교에서 제외합니다. 구입/대여 중 한쪽만 가능하면 가능한 가격·링크만 사용합니다. 품절 여부는 기존 `products.json`의 등록 상태를 따릅니다.
- 치수 비교가 주요 선택 기준이 아닌 배회감지기·구강세척기·미끄럼방지양말·요실금팬티는 제원표에서 제외합니다. 전체 상품 목록 `/catalog`에는 유지합니다.
- `src/data/specifications.json`: 직접 대조한 257개 원본 제원 기록. 모든 기록이 몰에 있는 것은 아니며 실제 표시 개수는 등록 상품과 매칭된 결과로 계산합니다. 치수 cm, 무게·하중 kg. 좌면은 가로 × 세로 / 높이 순입니다.
- `specification-audit.json`에 치수 비교 대상인 몰 등록 341개 모델의 대조 결과를 기록합니다. 246개는 원본 제원을 연결했고, 95개는 첨부 문서에 모델이 없어 `첨부 카탈로그 미수록`으로 표시합니다. 수록된 제품의 일부 수치가 원본에 없으면 `원본 미기재`, 적용하지 않는 항목은 `해당 없음`으로 구분합니다. null은 원본 미기재입니다. 향후 신규 모델이 추가돼 대조 기록이 없을 때만 `치수 미등록`으로 표시합니다. OCR 치수는 게시하지 않습니다.
- 모델명·급여코드 검색, 무게·가로 정렬, 2~4개 제품의 사진·가격·본인부담금·제원 비교, 다른 제원만 보기와 인쇄를 지원합니다. 선택 모델은 품목을 바꿔도 유지하며 개별 해제할 수 있습니다.
- 카탈로그 원본 보기 UI는 사용자 요청으로 제거했습니다. 출처 쪽수는 데이터 내부에 보존합니다.
- `public/catalog-2026/size-guide.webp`는 GPT로 제작한 일반 치수 안내 이미지입니다. 실제 제품 사진은 기존 몰 이미지를 사용합니다.

제원 추가 시 치수 화살표와 급여코드·쪽수를 직접 확인합니다. 가격과 재고는 기존 몰 데이터 기준이며 카탈로그와 다를 수 있습니다.

검증: `node scripts/catalog/check_specifications.cjs`, `npm run typecheck`, `npm run build`. 정적 출력은 `out/sizelist.html`입니다.

매트·방석·매트리스의 높이는 두께입니다. 지팡이 가로는 손잡이 폭 또는 명시한 바닥 폭이며 손잡이 폭을 통로 폭으로 해석하면 안 됩니다. 꺾임 손잡이는 각 변의 길이를 보존합니다. 매트리스 무게는 매트리스·펌프를 분리해 표기하고 정렬 시 첫 번째 명시 무게를 사용합니다.


### 기관 검색 조회 최적화와 캐시

- 검색 후보 목록은 좌표의 검색 범위를 0.02도 격자 경계까지 확장한 영역 키로 Cloudflare Cache API에 1시간 저장합니다. 실제 거리·반경 계산은 입력 GPS 좌표로 서버에서 수행합니다. 반경 검색 기능은 유지합니다.
- 품목·정렬은 캐시 키에서 제외하므로 같은 영역의 평가순·거리순·오래된순·종류 변경은 같은 후보 데이터를 재사용합니다. 캐시는 데이터센터별이며 만료·퇴거·다른 지역에서는 DB를 다시 읽습니다. 같은 인스턴스에서 동시 요청도 공유합니다.
- 주소 검색은 D1 없이 지도 API를 호출하며, 요청어 해시를 키로 결과를 하루 저장합니다. 사용자 개인정보·직원 API·장부 응답은 캐시하지 않습니다.
- 공개 조회에서 테이블 생성·마이그레이션·장부 데이터 정리를 실행하지 않습니다. 장부 정리는 종료된 장부 API에서만 수행합니다. 첫 후보 조회에서 `(lat,lng)` 인덱스를 가능한 경우 생성합니다. 조회 한도가 소진된 동안에는 인덱스 생성·첫 캐시 채우기가 제한될 수 있습니다.
- 좌표 입력 작업은 8곳마다 남은 전체 행을 세던 동작을 없앴습니다. 응답은 정확한 `remaining` 수 대신 `hasMore`로 다음 작업 여부를 알립니다. 관리 API 호출 스크립트는 이 값을 사용해야 합니다.
- 자료 갱신 시 `PUBLIC_CACHE_VERSION`도 변경해 이전 후보 캐시를 사용하지 않도록 합니다.
- 검증: `node scripts/check-care-cache.cjs`, `node scripts/check-retired-ledger.cjs`, 프런트 빌드 및 Functions 별도 타입 검사.

### 기관 상세정보 추가 연동

`/care/detail?c=기관기호`에서 기본정보와 공단 평가결과를 표시합니다. `/api/ltc/profile`은 설치신고일(`stpRptDt`)·지정일·전화번호와 인력 현황을 각 소스별로 조회하고 성공 응답만 하루 동안 엣지 캐시합니다. 키는 서버 환경변수에만 저장합니다.

- `DATA_GO_KR_KEY`: 시설별 상세조회 서비스(15058856)의 유효한 승인키가 필요합니다. 2026-11-14 키 변경 후 운영 API의 전화번호·설치신고일·지정일 정상 조회를 확인했습니다.
- 인력조회: 사용자가 활용가이드에서 확인한 `getStaffSttusDetailInfoItem02`를 사용합니다. 별도 오퍼레이션 환경변수 없이 `DATA_GO_KR_KEY`로 조회합니다.
- 조회 실패는 미등록·0명과 구분합니다. 설치신고일을 법인 설립일로 바꿔 표기하지 않습니다. 인력 수는 기관유형별 등록 수이며 현재 배정 가능한 인원이 아닙니다.
- 기준 문서: https://www.data.go.kr/data/15058856/openapi.do

### 기관 찾기 검색 상태 유지

검색 위치·입력한 동네·종류·정렬·반경·복지용구 탭과 최근 결과(최대 80개)를 같은 브라우저 탭의 `sessionStorage`에 임시 보관합니다. 마지막 변경 후 한 시간이 지나면 복원하지 않습니다. 최근 5분 내 동일 조건의 결과는 재사용하며, 그 이후에는 기존 목록을 보여주면서 새로 조회합니다. 조회 실패가 목록 초기화로 이어지지 않도록 이전 결과를 유지하고, 취소된 요청은 결과를 덮어쓰지 않습니다. 위치를 URL이나 별도 서버 저장소에 기록하지 않습니다.

회귀 검사: `node scripts/check-care-session.cjs` (화면 재진입·새로고침·탭 전환·실패·요청 취소·만료).

기관 상세 모바일 화면은 기관명·주소와 고정 전화/지도 버튼 아래에 인력·평가·기본정보 탭을 제공합니다. 인력은 주요 네 직종을 먼저 보여주고 전체 항목은 접어 둡니다. 요양보호사 합계는 1급·2급 값이 모두 있을 때만 표시합니다. 검증: `node scripts/check-facility-detail.cjs`.

### 월별 신규 기관 조회 시험

`GET /api/ltc/new-preview`는 서버의 공공데이터 키로 기관 검색 서비스의 지난달 등록 기관을 시험 조회합니다. 기본은 서울 은평구 방문요양(C01), 첫 페이지 10건입니다. `scope=seoul`은 서울 전체의 같은 기간·유형, `scope=control`은 청운노인요양원 한 곳의 기간 제한 없는 양성 대조 조회입니다. 이 세 가지 고정 시험 외에 쿼리로 기간·페이지 크기·유형을 바꿀 수 없습니다. 공개 응답을 5분 캐시하고 DB에는 접근하지 않습니다. API 거절과 정상 0건을 구분하며 표본의 지역·등록일 조건 충족 여부를 함께 반환합니다. 이 경로는 전체 수집·월별 예약·기관 등록 기능이 아닙니다.

검증: `node scripts/check-ltc-new-preview.cjs`. 운영 응답 확인 후 승인 여부·실제 데이터 필드·날짜 조건을 기준으로 본 수집기를 설계합니다.
